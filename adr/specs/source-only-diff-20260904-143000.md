# Spec: Source-only pull request diff

Date: 2026-09-04 · Status: draft for alignment
Intent: `adr/intent-focused-pr-review-20260904-143000.md`

## Summary

A pull request diff must show source code. It must not show generated files. It
must not count comment lines as changed lines. The reviewer keeps one control to
show everything again.

This spec changes pull request review only. Document review does not change.

## The problem

Plannotator detects generated files today. It does not act on the detection.
`packages/review-editor/App.tsx:536` records the limit:

> `// "generated" tag. Presentation-only — the diff data is never filtered.`

A generated file collapses. The file stays in the tree. The file keeps its line
count. A branch that changes 40 source lines still reports 2,800 changed lines.

Comment lines add the second error. `packages/shared/review-core.ts:2408` counts
every added line:

```ts
if (line.startsWith("+") && !line.startsWith("+++")) additions++;
```

A docstring change and a logic change count the same.

## The definition

This fork defines **source lines** as changed lines that meet both rules:

1. The file is not generated. `packages/shared/generated-files.ts` decides this.
2. The line is not a comment line and not a blank line.

The header reports source lines. The header also reports what it removed, so the
reviewer can always see that filtering happened.

## Part 1 — Remove generated files from the tree

Change the sidecar from a presentation hint into a filter.

**Server.** `buildGeneratedFilesSidecar` already returns the generated set at
`packages/server/review.ts:2043` and `:2514`. Keep that response field. The server
keeps returning every file, because the reviewer can turn filtering off without a
round trip.

**Client.** `packages/review-editor/App.tsx` holds `generatedFiles` today. Add one
state value, `showGeneratedFiles`, default `false`. The file tree, the file list,
and the diff body read the filtered set. Replace `expandedGeneratedFiles`, because
a removed file cannot be expanded.

**The control.** Put one toggle in the diff header beside the counts. The toggle
reads `Showing source only · 118 files hidden`. A click shows every file and the
label becomes `Showing all files`. Persist the choice per repository, next to the
existing panel view preference in `packages/ui/config/`.

Warning: never hide the fact that files are hidden. A reviewer who cannot see the
hidden count cannot tell a filtered diff from a small one. The count is not
optional.

## Part 2 — Stop counting comment lines

Add `packages/core/source-lines.ts`. The module answers one question: is this
changed line a source line?

```ts
export function isSourceLine(line: string, language: LanguageId): boolean
```

Python only for the first version, per the reviewer's instruction. The module
handles:

- A blank line, or a line that holds only whitespace.
- A line comment. The first non-space characters are `#`.
- A block string used as a comment. Python has no block comment, so the module
  tracks `"""` and `'''` and treats a line inside an unassigned string literal as
  a comment line.

Every other language returns `true` for every line until this fork adds its rule.
An unknown language must never under-count. Under-counting hides real change.

**Where the rule applies.** Two counters exist today and they duplicate each
other:

| counter | file | serves |
|---|---|---|
| server | `packages/shared/review-core.ts:2384` `listPatchFiles` | agent jobs, Guided Review |
| client | `packages/review-editor/utils/diffParser.ts` | the diff header and the tree |

The server counter says it "mirrors the client's" logic. Two mirrors drift. Move
the counting rule into `packages/core/source-lines.ts` and call it from both.

**The diff still shows comment lines.** This spec changes counting only. A comment
line renders exactly as it does today, because a comment gives the reviewer
context. Never filter a line out of the rendered diff.

## Test first

Write these before the implementation.

**Unit — `packages/core/source-lines.test.ts`.** Python cases, each as one line
plus the state before it:

1. `+    # explain the guard` is not a source line.
2. `+x = 1  # trailing comment` is a source line.
3. `+` alone is not a source line.
4. A line between two `"""` markers is not a source line.
5. `+    """docstring"""` on one line is not a source line.
6. `+s = """text"""` is a source line, because the string is assigned.

**Unit — filtering.** Given a diff of 5 files and a generated set of 2, the
filtered tree holds 3 files and the hidden count is 2.

**Integration — `packages/server/generated-files-endpoint.test.ts`.** Extend the
existing test. Point it at a fixture repository whose `.gitattributes` marks
`worldmodel/tests/**` generated and `-linguist-generated` on one file inside it.
Assert the negated file stays visible. This is the rule people get wrong, and git
resolves it for us.

**Manual — Playwright checklist.** Write the steps before the code:

1. Open a review on a branch with generated files.
2. The header reads `Showing source only`, and names a non-zero hidden count.
3. The tree holds no generated file.
4. Click the toggle. Every file appears. The label reads `Showing all files`.
5. Reload the page. The choice survives.

## Open question

The hidden count and the source-line count are two different numbers. The header
must carry both without becoming noise. Settle the header wording with the
reviewer before building it.
